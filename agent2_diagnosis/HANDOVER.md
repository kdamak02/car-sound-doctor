# Hand-over: Agent 2 and the full chain (Agent 1 + 2 + 3)

Written for whoever continues the project. Everything below was run on one Windows PC (RTX, 8 GB) in October 2026.
Facts are marked **measured** (a run or a test produced them) or **not tested**.

## 1. What exists

```
Telegram (NOT in the repo yet) -> n8n -> Agent 1 (audio, :8001) -> Agent 2 (diagnosis + checks, AI Agent node + rag_search tool, :8002 RAG)
                                              -> driver answers the checks (max 2 rounds) -> Agent 3 (repair guide, :8003)
```

| Part | Where | State |
|---|---|---|
| Agent 1, audio model | `agent1_audio/` (group A) | real models in `models/`, runs with `agent1_audio/start_agent1.ps1` (**measured**: OGG/Opus accepted, `unusable_audio` under 1.5 s, HTTP 400 on empty) |
| Agent 2 workflow | `n8n/workflows/*.json`, generated by `agent2_diagnosis/build_workflow.py` | **measured** working with Ollama, Groq, Gemini (Gemini only early on) |
| Agent 2 logic, prompts, RAG | `agent2_diagnosis/` (`agent2.py` = reference, `dev_rag/` = search service stand-in), `prompts/P3-P5`, `n8n/code_nodes/agent2_*.js` | 24 Python tests + Node tests pass |
| Agent 3, repair guide | `agent3_repair/` (group C, Groq model) | **measured** returns validated guides; content is generic (see section 5) |
| Hand-over Agent 2 -> 3 | `agent2_diagnosis/to_agent3.py` and `n8n/code_nodes/agent2_to_agent3.js` (same rules, same tests) | **measured** end to end |
| Test page | `agent2_diagnosis/streamlit_app.py` (:8501), switch "Chaîne complète" for the three agents | 6 headless tests pass |
| Telegram front (voice note, car, symptom, context buttons, checks as buttons, final guide) | `n8n/telegram_front/`, `n8n/workflows/telegram_front.json` | **measured** with a fake Telegram (`mock_telegram.py`); **not tested** with a real bot: see `n8n/telegram_front/README.md` for the 5 steps (BotFather token in the root `.env`) |

Branches: `integration/agent2-agent3` (everything, used by the whole team), `agent2/reranker` (PR 2: Agent 2 only), `agent2/diagnosis-logic` (PR 1).
Do not force-push `integration/agent2-agent3`: teammates push to it. Merge `origin/integration/agent2-agent3` before pushing.

## 2. Run everything

```powershell
# Docker Desktop must be running. -Python needs the packages of dev_rag + agent3_repair/requirements.txt (+ streamlit)
.\agent2_diagnosis\start_full_chain.ps1 -Python "C:\path\to\python.exe" -RagDevice cuda   # cuda = fast; use cpu with Ollama
```
It starts n8n :5678, Ollama :11434, RAG :8002, Agent 1 :8001 (first time: about 10 minutes to build `.venv-agent1`), Agent 3 :8003 and the test page :8501, then prints which are up.

Before the first run:
1. Copy `.env.example` to `.env` (root). Copy `agent3_repair/.env.example` to `agent3_repair/.env` and put `GROQ_API_KEY=` there. **Never commit a key**; `.env` is git-ignored. (A key once ended up in the tracked `.env.example`: check `git diff` before every commit.)
2. Manuals: put the owner's manual PDFs in `data/rag/raw/manuals/` and build the search index: `python agent2_diagnosis/dev_rag/ingest.py structure` and `... obdex` (see `agent2_diagnosis/dev_rag/manuals.json`). The index folder `agent2_diagnosis/dev_rag/index/` is git-ignored.
3. Ollama only: `ollama pull qwen2.5:7b`.

Import a workflow (n8n http://localhost:5678, menu "Import from file"): pick **one** of
`n8n/workflows/full_chain_ollama.json` (local, no quota), `full_chain_groq.json` (needs a Groq credential), `full_chain_gemini.json`.
Then open the model node and select the credential: Ollama base URL `http://host.docker.internal:11434`; Groq: the shared key; Gemini: your own key.
Activate it. **Only one** of these workflows (or `agent2_diagnosis.json`) may be active: they share the webhook paths.
Regenerate any of them: `AGENT1=true AGENT3=true LLM=ollama|groq RAG_URL=http://host.docker.internal:8002/search OUT=n8n/workflows/<file>.json python agent2_diagnosis/build_workflow.py` (options at the top of that file; `GROQ_MODEL_A2`, `RAG_TOP_K`, `RESCUE`, `SUPPORT_CHECK`).

## 3. Try it

```bash

curl -X POST localhost:5678/webhook/agent2-diagnose-audio -F audio=@note.ogg -F "case=<agent2_diagnosis/tests/cases/clio_starter_pass1.json"
# pass 2 (JSON case with round 1, the previous answer in `diagnosis` and `check_answers`): see tests/cases/clio_starter_pass2.json
```

Replies: `{agent1, agent2, agent3}` (agent3 is `null` while checks are pending), `{needs_new_audio, message}` for an unusable recording, `{insufficient, reason}` when the manuals do not support an answer.
Cases that the manuals cover (`agent2_diagnosis/tests/cases/README.md`): Clio starter/battery (p. 225), Clio oil pressure, Peugeot 208 charge light. **The demo case is the Clio that does not start (battery, context `startup`).** The manuals do not cover other noises: Agent 2 then answers `insufficient` on purpose.

## 4. Measured results (use them in the report; they come from small samples)

- Retrieval, 30 queries (`rag/eval/queries.jsonl`, written by one person): chunking by heading beats fixed windows; BM25 + dense beats dense; hit rate 0.846 (0.923 without the reranker and with the `maintenance` section); the bge-reranker rejects 4 of 4 out-of-corpus queries (1 of 4 without). Details and tables: `agent2_diagnosis/tests/eval_results.md`.
- Runs through n8n: Ollama 7B 37-69 s (reranker on CPU can make it 2-4 min), Groq `gpt-oss-120b` 8 of 8 usable on the four covered cases (power steering excluded: 0 of 2) until its daily budget ran out, `gpt-oss-20b` 5 of 10 (power steering excluded). Full chain on Ollama: pass 1 about 35-50 s, pass 2 about 52-59 s, Agent 3 valid in 2 of 2 tries.
- Prompt changes P4/P5 v2.4 and v2.5 with before/after: `prompts/` (Versions tables).

## 5. Known problems, most important first

1. **Agent 3 is generic.** Its corpus has no Renault/Peugeot fault-specific repair content; the starter case gets a "how to disconnect a battery" iFixit guide, one step reads "[... Step 6: Step 6]". It passes its own validation. Also a wrong warning ("Critical brake issue detected") appeared for an oil-pressure case. Both are group C's (Amir-benali); send them the evidence.
2. **Groq free tier**: 8,000 tokens per minute and 200,000 per day *per model* for the whole organization (shared with group C). One Agent 2 run uses about 7,000 tokens. Do not run test batches on the demo day. Fallback: Ollama.
3. **Power steering case is unstable** (the 7B and 20b models cite label names instead of passage ids, every cause is dropped, the answer is `insufficient`).
4. **7B model quality** (Ollama): duplicate labels, occasional English, asks checks that need tools. The rescue branch (`Agent answered?` / `Rescue prompt`) exists because it sometimes returns an empty answer.
5. **Speed**: the reranker is slow on CPU. On GPU (`-RagDevice cuda`) a search takes about 1 s, but then Ollama (5 GB) and the RAG (4 GB) do not fit together in 8 GB: use Groq/Gemini or CPU.
6. **The search service is a stand-in** (numpy store, not Qdrant); `agent3_repair` has its own Qdrant. Group B1 owns the shared service; the `/search` contract is the same (`contracts/rag_search.schema.json`).
7. **Evaluation set is small**; the citation support check looks at the cause name and the symptom, not the passage content alone (an unrelated OBDex code can still pass in the Python path).
8. **Never tested**: a real engine recording (group A prepares the demo recording; test it with the starter case), Telegram, Agent 1 with several users at once.

## 7. Troubleshooting

- `docker info` hangs or "pipe not found": Docker Desktop's engine is down. Quit it fully and start it again.
- "Error in workflow" with Groq: read the execution in n8n; the usual cause is the token limits above.
- Webhook 404 right after importing or restarting n8n: wait 15 s; also check the workflow is Active and only one is active.
- Git Bash mangles `docker exec` paths (use `MSYS_NO_PATHCONV=1`) and `taskkill /PID`; use PowerShell `Stop-Process` for the ports.
- Do not restart n8n, the RAG or Ollama during a test run: the run fails.
- The test page says "Impossible de joindre n8n": the page's time limit is shorter than the run (raise it in the sidebar, default 300 s) or Docker is down.
